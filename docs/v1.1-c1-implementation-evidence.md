## 4. Observer and fan-out architecture

```
InventoryScanner (validate, name the run)
   │ ScanStartInfo (run ID, enumerated root, canonical root, own names)
   ▼
ScanEngine ──OnFile/OnError──▶ ObserverFanOut ─┬─▶ OutputGuard ─▶ CsvReportSink     critical: exceptions abort as v1
                                               ├─▶ SpoolWriter ─▶ Stream             isolated: class A ⇒ faulted
                                               └─▶ (test observers)                   isolated
pipeline: Aggregate + Verify ─▶ OnFolderFinalised(i) for i = 0..n-1 ─▶ Folders report ─▶ sorted Files ─▶ OnScanEnded
```

**Order guarantees (SINK-03), as implemented.**

1. A scan refused at validation, or whose report folder cannot be prepared, calls no observer (v1 returns `RunId = ""`
   for both, so the run is not named). Otherwise every observer gets `OnScanStarted` first and `OnScanEnded` last,
   exactly once each, on every path (`ObserverFanOut.OnScanEnded` for a finished scan, `EndRemaining` otherwise).
2. `OnFile` and `OnError` are the engine's calls, forwarded: during enumeration only, one contiguous run of files per
   folder, depth-first pop order.
3. The n-th `OnFile` is v1's sequence n (the fan-out forwards in order; nothing is buffered or reordered).
4. `OnFolderFinalised` once per folder, ascending, `parentIndex < index`, root 0/-1, only after enumeration and
   aggregation (with `Verify`) completed, after the last file and error and before the Folders report is created.
5. The `OnFile`/`OnError` sequence and arguments are v1's, so report bytes are unchanged (§5).

**Critical versus isolated (SINK-04, SINK-05, D-11).** The CSV sink is the only critical observer and the only one
wrapped by `OutputGuard`, whose `IOException`/`UnauthorizedAccessException` mapping to `ReportWriteException` (so
`OutputError`) is v1's. An isolated observer's class A exception is caught by the fan-out, recorded as an
`ObserverFault` (the original exception, never wrapped), and the observer receives nothing more except
`OnScanEnded`. Delivery is synchronous on the scanning thread: no channel, queue or writer thread (REV-M03).

**Exception classes (CAT-01 to CAT-03, D-45).** `ExceptionClasses.IsCatastrophic`: `OutOfMemoryException` (and so
`InsufficientMemoryException`) and `InsufficientExecutionStackException`; never isolated, rethrown from every
callback. `IsCancellation`: `OperationCanceledException` while the run's token is cancelled; never isolated. Any other
exception from an isolated observer is class A. v1's top-level handler is unchanged: a class C exception still ends
the scan as `Failed (Unexpected)` with v1's message; `ObservedScanOutcome.Catastrophic` additionally reports it, as
CAT-03 asks `RunCapture` to do later. C1 does not decide anything from that flag (no Faulted state exists before C4).

**Internal only (SINK-09, D-46).** All of the above is `internal`. Core's `InternalsVisibleTo` list is still v1's
(`StorageInventory.Core.Tests`, `StorageInventory.IntegrationTests`), a subset of A-13's approved set. The public
surface equals v1's (TEST-O5). `ScanObserved` is the "internal InventoryScanner entry point accepting additional
isolated observers, for tests" of §19 C1; no public consumer API exists.

## 6. The spool codec, format 1

Implements SPOOL-20 exactly; the details the specification leaves to C1 are frozen here (G0F-O03) and pinned by
`SpoolCodecTests.Frozen_layout_of_format_1` and `Null_encodings_and_stable_codes_are_frozen`.

| Part | Layout (little-endian) |
|---|---|
| Header | `SISPOOL1` (8 ASCII) · format u16 = 1 · flags u16 = 0 · capture token (16 bytes) · run ID length u16 (1..256) + UTF-16 · `scanner_contract` u16 = 1 · created UTC ticks i64 |
| `0x01` file | folder index i32 · name length **u16** + UTF-16 · size i64 · created, modified, accessed ticks i64 · attributes i32 (43 bytes + 2 × name) |
| `0x02` error | type u8 · path length u32 + UTF-16 · message length u32 + UTF-16 (10 bytes + 2 × (path + message)) |
| `0x03` folder | index i32 · parent i32 · name length **u16** + UTF-16 · status u8 · status reason u8 · subtree complete u8 · attributes i32 · created, modified ticks i64 · direct bytes, total bytes, direct files, total files, direct subfolders, total subfolders i64 · largest file bytes i64 (90 bytes + 2 × name) |
| Run index | per run in emission order: folder index i32 · absolute offset of the run's first file record i64 · count i32 (16 bytes) |
| Trailer (113 bytes) | `0x7F` · file records, error records, folder records, runs i64 · totals: files, folders, bytes, scan errors, reparse points skipped, file reparse points, locally incomplete folders, affected ancestor folders i64 · folder-section offset i64 · run-index offset i64 |
| Digest | SHA-256 of bytes `[0, L − 32)`; the last 32 bytes; nothing follows |

* **Nulls:** ticks and the largest-file size use `long.MinValue`; a missing status reason is `0xFF`.
* **Flags:** format 1 defines none; V rejects any non-zero value.
* **Codes:** the explicit stable codes of §9.4 (`ScanErrorType` 1 to 9, `FolderScanStatus` 0 to 3), never enum ordinals.
* **Counts to totals:** file records = `Files`; error records = `ScanErrors` + `ReparsePointsSkipped` +
  `FileReparsePoints` (informational reparse rows are error records); folder records = `Folders`.
* **Names:** written as the string's UTF-16 code units copied directly (no `Encoding`, so no replacement character);
  read back with `new string(...)` over the same units.
* **Sequences:** a file record's sequence is its position among file records (v1's tie order); a run carries its
  first sequence.

**Writer** (`SpoolWriter`, isolated observer). Appends in emission order through one 1 MiB buffer; every flushed
byte is fed to an incremental SHA-256 before it is written, so the digest covers write order, which is physical order
because nothing is rewritten (SPOOL-07, SPOOL-12). It refuses streams that break SINK-03 (a folder's files not
contiguous, folders out of order or not starting at the root, records after the folder section, a non-empty
destination) by faulting itself. It seals only on `OnScanEnded(Finished)` and only when its own counts and the
statuses it recorded equal all eight `ScanTotals` fields; it then writes the run index, trailer and digest and flushes
(no fsync, SPOOL-12). A cancelled or failed end abandons it; any exception while writing faults it for good; neither
ever writes a trailer. It never closes the stream: in C1 the stream is the caller's, and the file and its exclusive
delete-on-close handle are C5's (SPOOL-02, SPOOL-04).

**Reader.** Only `SpoolReader.Verify` creates a `VerifiedSpool` (an audit rule enforces it). `VerifiedSpool` reads a
run by seeking to its offset (the key-ordered access of IMP-03), the folder section, the record region in physical
order, or the error records; it re-checks the stream length on every refill and throws if a record no longer parses.

## 7. Integrity and structural validation (pass V)

**One sequential read** of the stream from offset 0 (SPOOL-23, D-50). The pass feeds bytes `[0, L − 32)` to SHA-256
and keeps the last 32 bytes, while a parser walks the structure on the same bytes. If the structure breaks, parsing
stops but reading continues to the end, so the digest is always computed; **a digest mismatch is reported in
preference to any structural defect.** The token is checked every 64 MiB (the CAN-01d cadence, for C5).

| Step (SPOOL-23) | Checks | Defect |
|---|---|---|
| (1) | `L ≥ 185` (header + trailer + digest); digest | `TooShort`, `DigestMismatch` |
| (2) Header | magic, format 1, flags 0, capture token, run ID length 1..256, scanner contract 1, created ticks valid | `BadMagic`, `UnsupportedFormat`, `UnsupportedFlags`, `CaptureTokenMismatch`, `BadHeader` |
| (3) Records | tags `0x01`/`0x02` until the first `0x03`; every length within the bytes before the trailer; folder index ≥ 0; size ≥ 0; ticks valid or null; error codes 1..9 | `BadRecordTag`, `RecordOutOfBounds` |
| (4) Runs | runs rebuilt from the records (errors allowed inside); no folder index starts two runs; equal to the stored run index entry by entry | `RunSplit`, `RunIndexMismatch` |
| (5) Folders | n = root's total subfolders + 1 (bounded by the bytes available); indexes 0..n−1 ascending; parent below child; a run's folder exists | `FolderSectionInvalid` |
| (5) Closure | a child folder or file run only inside a listed (Ok or Partial) folder; direct files and bytes equal the folder's run; direct subfolders equal the children that follow; Unreadable/Partial never complete; incompleteness reaches every ancestor | `FolderClosureViolation` |
| (5) Totals | root totals equal the records; the eight totals recomputed from records and folders equal the trailer's; the trailer equals the scan result's totals | `TotalsMismatch`, `ResultTotalsMismatch` |
| (3)/(6) Trailer | per-tag counts; trailer tag, run count and both offsets equal the positions found | `RecordCountMismatch`, `TrailerInvalid` |

The closure checks mirror `FolderAggregator.Verify` and §9.5 invariants 2, 3, 5, 8 and 9 at spool level. They are
stricter than the minimum SPOOL-23 lists (§14), and cannot reject a spool the writer produces, because the writer only
receives folders that passed `Verify`.

**What V proves, and what it does not (G0F-M07, D-50).** The digest proves byte integrity relative to the seal. The
structural steps prove consistency even against a rewrite that recomputes the digest. Neither proves order or content
against an outside authority: two file records of the **same** folder exchanged within its run, or names exchanged
while every folder index stays in place and the run index still matches, are accepted. TEST-SP7 asserts exactly that
boundary. SHA-256 here is integrity relative to the seal, **not** evidence of semantic or historical authenticity.

**TEST-SP7 (corrected form), all in `SpoolIntegrityTests`:**

| Class | Cases | Expected and observed |
|---|---|---|
| Byte integrity, digest not recomputed | one byte changed (three masks) in the header run ID, header time, a file record, an error record, a run read out of key order, the folder section, the run index, a trailer field, the trailer tag, the digest; truncation at 14 offsets; 1, 8, 32 and 1,000 bytes appended; zero digest, digest of a shorter or longer range, another hash | `DigestMismatch` (or `TooShort`) every time |
| Structure, digest recomputed | run split; whole records of different folders exchanged (single-record runs: `RunIndexMismatch`; into a multi-record run: `RunSplit`); run-index entries reordered; unknown tag; trailer tag in the record region; lengths, codes, sizes, ticks, folder index out of bounds; per-tag counts; folder index out of order, parent not below child, root with a parent, a non-folder in the section; six closure violations; each of the eight totals; the result's totals; both offsets, the run count and the trailer tag; magic, format, flags, token, scanner contract, empty run ID | the named structural defect every time |
| Documented boundary | same-folder exchange (equal and different sizes); names exchanged within one run; names of equal length exchanged across runs; names of different lengths across runs with the run index rewritten to match | **accepted**, and the read-back shows the exchange |
| G0E-O09 qualification | names of different lengths across runs, run index left as it was | rejected (`RunIndexMismatch`); qualified in the test's comment as G0E-O09 asks |
| Fuzz | 4,000 one-byte rewrites, re-sealed | never a crash, never `DigestMismatch`; either accepted (a byte inside a name, time or attribute) or a structural defect |

comparison or the parent-order check each made between two and four TEST-SP7 tests fail.

## 8. Cancellation and failure

| Situation | Scan result (v1's) | Observers | Spool |
|---|---|---|---|
| Cancelled during enumeration (CAN-01a; spool writes inside callbacks, CAN-01b) | Cancelled; created reports listed as incomplete | every started observer gets `OnScanEnded(Cancelled)`; no folder is finalised | writer `Abandoned`, no trailer; V rejects |
| Cancelled during finalisation | Cancelled at the Folders report's first check (as v1 during aggregation) | all folders finalised, then `Cancelled` | `Abandoned` |
| Cancelled during the Folders report or the sorted copy (CAN-01c) | Cancelled (v1's token checks) | `Cancelled` | `Abandoned` |
| Isolated observer, class A | unchanged (Complete/Incomplete); reports byte-identical | that observer faulted, recorded with its original exception; others unaffected | a faulted writer never seals, even if then told "Finished" |
| Isolated `OperationCanceledException`, token set | Cancelled | — | — |
| Class C anywhere (an observer, the engine) | `Failed (Unexpected)`, v1's message; never Finished, so never a capture candidate | remaining observers ended `Failed`; `Catastrophic = true` | never sealed |
| Critical I/O failure | `Failed (OutputError)` (v1) | isolated observers were started first and are ended `Failed` | `Abandoned` |
| End notification throws after the scan already failed | unchanged | each observer ended in its own guard; class C during this stops the notifications and sets `Catastrophic` | — |

**No cancelled or failed run can yield a spool that later gates could mistake for a snapshot candidate:** a spool is
sealed only after `OnScanEnded(Finished)`, which the pipeline sends only after v1's reports are complete and only to an
unfaulted writer whose counts match the totals; any other end leaves no trailer and no digest, and V rejects it. C5's
eligibility additionally requires `StorageScanResult.Finished` (LIFE-08). No file is involved in C1, so there is
nothing to clean up; RX-02's delete-on-close cleanup is C5's (§13).

## 9. One traversal, final-only folders, exact names, bounded memory

**One traversal (SINK-01).** Structurally: only `ScanEngine.cs` contains any enumeration API, only
`InventoryScanner.cs` constructs a `ScanEngine` (once) and calls `Run` (once), machine-checked by
`SecurityAuditTests.C1_observer_and_spool_capabilities_appear_only_in_their_audited_places`. At run time:
`One_traversal_feeds_every_observer` shows two observers receive the **same object instances** (each
`ScanErrorRecord`, each file record's `FullPath` string, each `FolderInventoryRecord`) from one emission.

**Provisional versus final (SINK-08).** `IScanObserver` has no discovery member (asserted by reflection). Folder state
lives only in `ScanEngine.Folders` until `Aggregate` + `Verify`; then each folder is emitted once.
`TEST_O1_a_folder_is_emitted_only_with_its_final_status` lists two folders as ordinary folders, then turns one into a
junction and deletes the other before they are entered: their only emissions carry `ReparsePointSkipped` and
`Unreadable (NotFound)`, the root's emission is incomplete, and no folder call precedes the last file call. Every
finalised record equals the Folders report's row for the same folder on every fixture.

**Exact names.** Strings are copied as code units both ways. Core.Tests round-trip unpaired surrogates (high, low,
reversed), surrogate pairs, NFC/NFD and case variants, formula characters, `NUL`, `U+FFFE`/`U+FFFF`, zero-width and
255-unit names. On NTFS, `Exact_filesystem_names_survive_the_spool_unnormalised` creates (empty) files named with an
unpaired surrogate on each side, NFC and NFD spellings as two siblings, trailing dot and trailing space (through
`\\?\`), a leading `=`, an emoji and a 255-unit name; the observer's names, the spool's names and an independent
listing are equal ordinally. No file content is opened. No comparison key, case folding or normalisation exists in C1.

**Bounded memory (SPOOL-21, INV-13).** The writer keeps one 1 MiB buffer, the hash state, 16 bytes per run and one bit
per folder index; nothing per file. Measured by `SpoolMemoryTests` (Windows CI): writer retained memory 8,184 B at
200,000 files and 16,384 B at 2,000,000 files (1,000 folders); pass V allocated 1,181,168 B for an 11 MB spool and
1,173,392 B for a 109 MB spool. V keeps a few bytes per folder and per run.

## 14. Judgement calls for the reviewer

Each is a reading of the specification, not a new contract; each can be reversed locally.

1. **"Before the run is named."** A scan whose report folder cannot be prepared calls no observer, because v1 returns
   `RunId = ""` for it, exactly as for invalid paths.
2. **`OnScanStarted` order.** Isolated observers are started before the critical one, so that every isolated observer
   is started (and then ended) even when the critical observer cannot create its reports. All other callbacks go to
   the critical observer first.
3. **CSV files created in `OnScanStarted`** instead of the sink's constructor (§5); the reports' names, order, timing in
   the pipeline and error mapping are unchanged.
4. **`OnScanEnded(Finished)` timing.** Sent after the result has been built (after v1's last report step), so
   `PhaseTimings.Total` excludes the spool's seal; finalisation is inside `Aggregation`.
5. **Ending after failure.** `EndRemaining` ends every started observer in its own guard and drops the critical
   observer's exceptions there (the outcome is already v1's). A class C exception while ending stops the notifications
   and sets `Catastrophic`, mirroring OBS-13's best-effort release.
6. **V is stricter than its minimum.** Closure checks (§7) and value bounds (sizes, ticks, codes) beyond SPOOL-23's
   list; they mirror `Verify` and §9.5 and cannot reject a writer-produced spool.
7. **The writer self-checks** its counts and statuses against all eight totals before sealing, and refuses SINK-03
   violations; a defect upstream therefore produces an unsealed spool instead of a sealed wrong one.
8. **`ScanStartInfo.CanonicalRoot`** is read through v1's existing function once per named run; information only.
9. **A-13 in C1.** `InternalsVisibleTo` is kept at v1's two test assemblies, a subset of A-13's six; the History and
   Library entries are added by the gates that create those assemblies. This also keeps G0E-O07 (a)'s exposure of
   `ScanEngine` and `ScanObserved` to those assemblies from arising before C5's deny rule.
10. **V's cancellation check** every 64 MiB is a codec capability; C5 wires it to the save token (CAN-01d).
