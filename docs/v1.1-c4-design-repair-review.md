# StorageInventory v1.1 C4 design repair review: the seven re-review findings of D-52

This is a focused, independent re-review of the bounded repair of decision D-52 (`docs/v1.1-c4-design-repair.md`, branch
`v1.1/c4-design-repair`). It answers one question: **did the repair correctly close the one High and six Medium findings of the D-52
re-review (`docs/v1.1-c4-design-rereview.md`) without introducing a new Blocker, High or Medium design defect?**

It does not repeat the C4 architecture review. It does not repair C4, start C5, or change any production source, test, specification
text or evidence file. D-52's architectural core was accepted by the re-review and is not reopened here: one rollback-journal T-IMPORT,
atomic publication, the per-source name dictionary, no hidden staged commits, no mandatory key-ordered interning, the 64 MiB import
cache, and structure, space and stop/recovery bounds in place of the old PERF-15.

Units: **MiB = 2^20 bytes, MB = 10^6 bytes**; decisive figures are also given in bytes. Every figure carries one of these labels:

- **measured here**: run or computed in this review;
- **from the evidence**: recomputed from the repair's committed raw files;
- **from source**: read in SQLite's or StorageInventory's code;
- **inferred**: argued, not measured.

### 5.3 Generator correctness

**From source** (`ObjSnapshot` and `ObjNames` in `harness.patch`):

- **Exact distinct count.**
  - V = round(d·n) over the base snapshot's n files.
  - Slot t = (slot·a + b) mod n is a permutation, because a is advanced until gcd(a, n) = 1.
  - So exactly V slots map below V and receive each entry once.
  - Every repeat is drawn from [0, V) and re-drawn on a same-folder collision.
  - The distinct count is therefore exactly V.
- **Distinct names.**
  - An entry starts with five letters that encode a bijective scramble of its index over 52^5 (the scramble constant is odd and not a
    multiple of 13).
  - So entries of one vocabulary are distinct, and spread uniformly over the key space.
  - Folder names (`dir` + digits) can never equal a file name (file names have five leading letters).
- **Re-scan.**
  - Renamed files take index V + n·layer + slot, which is outside [0, V) and unique per layer, so the name is new to the source.
  - Added files take a vocabulary rank, so the name already exists.
  - Deletion, renaming and addition are per-file Bernoulli draws. The realised fractions are therefore close to ρ, δ and α, not exact
    (C4DRR-O10).

**Measured here** (`repair:smoke`, 100k) and **from the evidence** (2M):

| Cell | Files | Distinct | Check |
|---|---:|---:|---|
| F(100k, 25%, system), new source | 100,247 | 25,062 = round(0.25 × 100,247) | importer's new names 26,060 = 25,062 + 998 folder names |
| R(100k) 1% / 0.5% / 0.5% | 100,437 | – | renamed 1,039 = importer's new names 1,039; of a 100,426-file base: ρ 1.035%, δ 0.528%, α 0.539% |
| F(2M, 25%, system) | 1,997,023 | 499,256 = round(0.25 × 1,997,023) | importer 500,254 = 499,256 + 998 |
| R(2M) 1% / 0.5% / 0.5% | 2,001,522 | 516,090 | renamed 20,016 = importer's 20,016; of a 2,001,707-file base: ρ 0.99995%, δ 0.504%, α 0.495% |
| F(2M, 60%, data) | 1,997,023 | 1,198,214 (60.00%) | importer 1,199,212 |

**Rounding.** `Math.Round` uses banker's rounding at .5. This is harmless, because no class depends on V. The realised statistics
straddle the boundaries: 25.00001% distinct at d = 25%, and ρ = 1.035% at 100k. So a classification by realised values would flip
cells. The repaired rule correctly uses input parameters only (§5.4).

### 5.4 Classification by input parameters

The repaired §15.4 states the following.

- Every cell is defined by numeric parameters fixed before it runs.
- A run's class follows from its cell's parameters alone and never from its result.
- No outcome moves a cell, and a slow representative run stays representative.

Nothing in the text, the harness or the evidence uses a result to classify. **The result-dependence of the old cells is removed.**

### 5.5 The class rule as written (measured here)

The class table's rows are nested upper bounds:

- representative: model system, d ≤ 25%; re-scan ρ ≤ 1%, δ ≤ 0.5%, α ≤ 0.5%;
- stress: d ≤ 60%; re-scan "as representative, but ρ ≤ 10%, δ ≤ 5%, α ≤ 5%";
- worst-case: d > 60%; ρ > 10%; or a dictionary in which every name is distinct.

The tie-break is "a cell whose parameters fit several rows takes the hardest of them". Each cell was classified by the rule exactly as
written, and by the reading the matrix's own labels imply:

| Cell | Literal rule (rows it fits) | Intended reading |
|---|---|---|
| F d = 25.0% system (**matrix: representative**) | **stress** (representative and stress) | representative |
| F d = 25.0% + ε system | stress | stress |
| F d = 60.0% data (matrix: stress) | stress | stress |
| F d = 60.0% + ε data | worst-case | worst-case |
| R ρ = 1%, δ = α = 0.5% (**matrix: representative**) | **stress** (representative and stress) | representative |
| R ρ = 1% + ε | stress | stress |
| R ρ = 10%, δ = α = 5% (matrix: stress) | stress | stress |
| R ρ = 10% + ε | worst-case | worst-case |
| R ρ = 1% of a 60% data-model source (a routine re-scan of a high-novelty source) | **no row: Informational** | no row |
| R ρ = 1%, δ = 8% | **no row: Informational** | no row |

The rule never uses a result, and the 60% and 10% boundaries behave as intended. The defects are two:

- **The representative class is empty under the stated rule.** The matrix's labels contradict the rule.
- **The rule is not total.** A re-scan of any source whose first save was not representative, and a re-scan with δ or α above 5%, fit
  no row and fall to "Informational: every cell outside the matrix".

The first is a wording defect with an obvious intent. The second contradicts D-53's product decision. D-53 says high-novelty real
sources are "bounded by PERF-14's engine target and the 5 s Stop budget". Yet the operation those sources undergo most often, the
routine re-scan, has no class and no budget. **C4DRR-M01.**

### 5.6 Benchmark-family justification

- **Representative first save (system model, d ≤ 25%).**
  - Basis: every whole source of 0.5M to 2.6M files on the reference drive (18.0% to 22.9%), and SRCH-02's projection of 12.5%.
  - Judgement: defensible as a predeclared product bound for large system-like sources.
  - The spec says plainly that one workstation does not represent every user.
- **Stress (d ≤ 60%).**
  - Basis: the measured data volume (59.1% as a whole), on its own name model.
  - Judgement: defensible.
- **Worst-case (above 60%, up to all distinct).**
  - Basis: the measured subtrees, which run to 100%.
  - Judgement: defensible.
- **Re-scan rates (1% routine; 5% and 10% stress).**
  - They are defined, not measured: the creation-time proxy was unusable, as the census shows.
  - TEST-P2 measures the real rate with two captures 7 days apart and raises the representative ρ by reviewed change if the real rate
    is higher. That is an adequate safeguard against a convenient choice.
- **Size independence.** The thresholds come from whole sources of 0.5M to 2.6M files but apply at any n. Smaller real trees are
  48% to 100% distinct (C4DRR-O10). The matrix holds only 1M and 2M cells, so no gate is affected.

**Verdict on breadth:** first saves cannot be excluded by construction. Re-scans can: a re-scan of a high-novelty source sits outside
every class (C4DRR-M01).

### 5.7 D-53

D-53 is explicit and reviewed. High-novelty first saves and high-churn re-scans of representative sources are stress cells. They are
held to PERF-14's 45 s engine target (MET required at C4, stop above 67.5 s) and to the 5 s and 4.75 s Stop budgets. They are not held
to PERF-01.

So for those cells it does **not** say "slow realistic workloads do not count": a stress cell slower than 45 s fails C4. It does,
though, leave the routine re-scan of a high-novelty source without any target (C4DRR-M01).

**C4DR-H01: CLOSED.** The objectivity, the calibration, the parameter-only rule and the product decision are all in place. The new
defect in the class mapping is C4DRR-M01.

### 6.2 The normative text (read in IMP-11)

- **Pending growth.** `Λ` = max(0, `P` × `S` − `L`). `P` is `PRAGMA page_count` on the writer inside the transaction, `S` the page size
  and `L` the main file's length through a handle.
- **Periodic check** (at `BEGIN` and after every 4,096 inserted rows of any table): `R_k` = `M_L` + `Λ_k` + `I_L`, with
  `I_L` = 2 × max(16 MiB, `D_k`).
- **Final check** (after the verification and the final statements; nothing runs between it and `COMMIT`): `R_f` = `M_L` + `Λ_f` +
  `R_C`, with `R_C` = 1 MiB.
- **Decision.** Continue when `F_L` ≥ the required value; equality continues. A lower value, or any input that cannot be read (the
  free-space query, `page_count`, the page size, the main length), rolls back as `LibraryFull`.
- **Guarantee.** It is stated as StorageInventory's own model. External consumption is named a residual race, caught by a guard stop
  or by `SQLITE_FULL`.

### 6.4 Does `Λ` conservatively model `COMMIT` growth? (from source, SQLite 3.53.3)

- **The write-out.**
  - `pager.c` 6710–6715: at commit phase one, if the image is larger than the file (`dbSize > dbFileSize`), the file is extended to the
    image by `pager_truncate`.
  - The dirty pages are written by `pager_write_pagelist`. So after `COMMIT` the file is exactly `P` × `S`.
  - `Λ` = `P` × `S` − `L` is therefore the exact file-length growth still to come. The measured 0 B differences are this mechanism,
    not luck.
- **Edge cases:**
  - **The lock-byte page.** If `P` equals the pending-byte page, the file ends one page short. `Λ` then overestimates by one page,
    which is conservative.
  - **`page_count` falling.** No auto-vacuum is configured: no setting exists in `src/`, and the default is `NONE`. So `P` never falls
    inside T-IMPORT. If `L` > `P` × `S` (trailing allocated pages), `Λ` = 0 and `COMMIT` truncates, which is conservative.
  - **Free-list reuse** consumes no new file length.
  - **The page size** cannot change inside a transaction.
  - **`page_count` changing before `COMMIT`:** nothing runs between the final check and `COMMIT`.
- **Chunked growth.**
  - `pager.c` 4500–4503 sends `SQLITE_FCNTL_SIZE_HINT`, and `os_win.c` 3629–3637 acts on it only when a chunk size is set
    (`szChunk > 0`).
  - StorageInventory sets no chunk size: there is no `CHUNK_SIZE` in `src/`.
  - So there is no pre-extension beyond the image.
- **The journal.** A record is written when its page is first changed, so the journal's length is current at every check, and `COMMIT`
  appends no record. This is measured, and it agrees with the format.

**Verdict:** `Λ` is **structurally exact for file length**, not merely empirically valid.

**What is not structural:** the step from file length to free space, that is cluster rounding and NTFS metadata. That is what `R_C`
covers. The repair's instrument measured file lengths, not drops in free space. The specification's sentence "the second condition holds
by construction (exact in every measurement)" is therefore slightly broader than its evidence (C4DRR-O03).

| Equality and failure | Equality continues. One byte below, or any input that cannot be read, rolls back as `LibraryFull` (class A). Consistent with TEST-L9 |
| Query and read failures | The free-space query, `page_count`, the page size and the main length are each named |

### 6.6 The periodic allowance

- **What the text says.** IMP-11 calls `I_L` "an allowance, not a bound". It gives a case that could exceed it: 4,096 new
  255-character names, each landing in an untouched leaf. It says the excess is caught at the next check, having used at most the
  excess of the margin.
- **What the model needs.** It is stated conditionally: if each interval's growth stays within `Λ_k` + `I_L`, the volume stays above
  the margin. The backstops remain later checks, the final check, `synchronous = FULL` and rollback.
- **No absolute guarantee survives elsewhere.**
  - §19 C5 requires measured intervals within their allowances, and the residual race "reported, not claimed away".
  - §15.2 only says IMP-11 checks the space.
  - A search for "guarantee", "never takes", "never below" and "by construction" found nothing absolute about IMP-11.
- **One evidence nit.** The quoted "at most 1.5 MB per 4,096 rows" (and 11.3 MB in the worst-case cell) is not a maximum over 4,096-row

## 7. C4DR-M02: PERF-15 (a) key-range confinement

### 7.1 Closure worksheet

| Original defect | Required closure | Repair claims | Independently verified? |
|---|---|---|---|
| B-tree attribution cannot see source ranges; real rebalancing (an adjacent interior page) was rejected; the new-source right edge was ambiguous | A per-level rule (in-range pages ± 2 positions, plus ancestors); key-range attribution in §15.4 and TEST-P1 | Per-level IN / ADJACENT (W = 2) / REMOTE / SHARED (≤ 6); the status of W; the first key column and divider intervals decoded; a required negative control | **Yes for the rule, the source claim and the controls** (§7.2 to §7.5). **The checker fails open on bad input: C4DRR-M02** (§7.6) |

### 7.2 The exact text (PERF-15 (a), §15.4)

The rule, as worded:

- **Where it applies:** in each source-prefixed dictionary index, at every level.
- **The W rule:** every journalled page lies within W = 2 positions of the run of pages whose divider-derived key interval intersects
  the target source. For a new source, that run is the rightmost page.
- **The shared cap:** at most 2 × (W + 1) = 6 journalled pages per level hold another source's entry.
- **Append-shaped trees:** the rightmost page of each level plus W pages to its left.
- **Also allowed:** catalogue trees, page 1 and free-list pages.
- **Any other page:** a defect, and the outcome is MISSED.

The status of W is stated:

- **From source:** one balancing step reaches at most two positions.
- **Not proven:** several steps at a range's border could reach further.
- **Observed:** the largest distance is 2 at a new source's edge and 1 beside an existing range.
- **Treatment:** a REMOTE page is never waived, and W changes only by reviewed change.

The text keeps three things apart: the **source-derived local bound**, the **empirical multi-step behaviour** and the **acceptance
tolerance**.

### 7.3 The W = 2 source claim (from source)

- **Fetched.** Upstream `src/btree.c` at the `version-3.53.3` tag. Its SHA-256 is
  `c0982890bcd01b479c66066030e32d15b88a2dce2dd9fd67fa301211555f7a94`, the hash the repair cites. The shipped `e_sqlite3.dll` reports
  version 3.53.3 with source id `2026-06-26 20:14:12 d4c0e51e…`.
- **One step.**
  - Lines 7519–7520: `NN 1` and `NB 3`.
  - The comment at 8206: "redistributes cells on the iParentIdx'th child of pParent … and up to 2 siblings".
  - Lines 8311–8325 select the siblings: `nxDiv = iParentIdx-1`, or `0` for the first child, or `i-2+bBulk` for the last child.
  - So one `balance_nonroot` reads the page and at most two siblings under one parent, both from one side at an edge: at most two
    positions away.
  - New sibling pages come from the free list (allowed) or from beyond the file's end (never journalled).
- **Upward chain.** `balance()` (9130–9253) loops up the tree. Each level's step sits on an ancestor of the changed page, and an
  ancestor of an IN page is IN at its level, so the bound holds per level for one step.
- **Chains are not covered.** A step can move the target's keys into a sibling, and a later insertion there can balance one position
  further. The specification says exactly this and does not stretch the claim.

This review's own reruns, from the committed patches, reproduced every journal of `repair:structure` **to the byte**. `journal_ranges.py`

The checker distinguishes the architectures for the intended reason. A Library-wide index makes an import journal pages that hold other
sources' entries; the per-source index does not.

**The shared cap (brief §22).** It is coherent, but derived rather than independent.

- **Derivation.** Keys sort by `source_id` first. Only the two end pages of a level's IN run can hold another source's keys, and each
  ADJACENT page (at most W per side) holds only other sources' keys. So with no REMOTE page, SHARED ≤ 2 + 2W = 2 × (W + 1).
- **What follows.** In the per-source layout the cap is implied by W. Its discriminating role is the existing-source negative control,
  where IN covers the whole index. It inherits W's empirical status.
- **The text** states the cap without this derivation (C4DRR-O05). It is not an independent correctness theorem, and it is not
  presented as one.

### 7.6 Does the checker fail closed? (measured here)

Thirteen cases were run on the 100k per-source re-scan journal (389 records; baseline PASS):

| Altered input | Checker result |
|---|---|
| Empty journal (0 bytes, what a copy after `COMMIT` gives) | **PASS** (0 records) |
| A journal of zeros | **PASS** (0 records) |
| First header magic corrupted | **PASS** (0 records: parsing stops silently) |
| One record's checksum corrupted | **PASS** (1 checksum failure reported) |
| One image byte the checksum does not sample changed | **PASS** (1 image mismatch reported) |
| Journal truncated to half | **PASS** (194 of 389 records) |
| Database copy of another run | **PASS** (1 image mismatch reported) |

**Root cause.**

- The verdict is `PASS if remote == 0 and not defects and not shared_over`.
- Checksum failures, image mismatches and truncation are reported but never change the verdict.
- An unparseable or empty journal yields zero records and therefore PASS.

**What the specification says.** §15.4 says "every record's checksum is verified and its original image compared byte for byte with the
copy", but never what a failure means. D-R4 makes `journal_ranges.py` "the reference or is ported".

**Consequence.** A literal port would let a TEST-P1 cell report PERF-15 (a) **PASS** on a journal copied too late, truncated or paired
with the wrong copy. The per-session negative control catches a systematically broken copy, but not one bad run. **C4DRR-M02.**

**C4DR-M02: CLOSED.** All three original problems are fixed, and their fixes were reproduced: key-range attribution, real rebalancing

### 8.3 Detection cadence: both dimensions

- **Rows.** The row cadence is an implementation obligation: 4,096 inserted rows; 65,536 rows examined per verification query.

### 8.4 Can the verification honour it? (from source; measured here)

- **Verdict:** both are bounded redesigns of the verification, and both are feasible. The 0.5 s bound is then a measurable target.

**Pairing edge cases:**

- **Duplicate `svchost`:** handled by the occurrence key.
- **Process exits:** PDH renumbers the later instances of the same executable. The PID comparison catches every shifted key, and the
  sample is discarded.
- **PID reuse within 500 ms at the same key:** extremely rare. Such a rate would be negative or garbage, and PDH marks negative rates
  invalid.
- **Missing entries:** caught as a length or name misalignment.

The pairing is therefore correct. **Discarded data is recorded only as sample counts, never as CPU.**

### 10.3 Quiet rule and session discipline

- **Quiet check.**
  - 60 s, external + induced CPU: mean ≤ 5% and p95 ≤ 15%.
  - Before the session: on failure the session does not start and the refusal is recorded.
  - After every round: on failure the round is invalid and its runs are kept and marked.
  - Replacement runs follow for invalidated runs. That runs of an invalid round count as invalidated runs is implied, not stated
    (C4DRR-O08).
- **Session.**
  - Declared before it starts, by a manifest that records whether it is the gate session.
  - The first complete session on the frozen implementation is the gate session.
  - Exactly five measured runs per cell, after one logged, unrecorded warm-up.
  - At most five replacement attempts, each only for an earlier run invalidated by the environment.
  - No valid run is ever discarded or replaced because of its result.
  - A new session only after a documented objective invalidation.
  - Every session reported.
- **Retry-until-pass.**
  - No loophole remains within one implementation.
  - Moving to a new "frozen implementation" restarts the gate designation, so a trivial commit could buy a fresh session. Every
    earlier session must still be reported in the output (C4DRR-O08).
- **Median:** the median of the **first five valid runs in run order**, with the minimum and maximum. Not the best five. The warm-up is
  separate.

### 10.4 Adversarial load (measured here)

Two 20-second probes were taken on the same machine. The second was taken while four short-lived CPU-bound processes (each about
0.3 s) ran continuously: 261 processes spawned in 24 s.

| | External | Induced | Own | Whole machine (PDH `_Total`) | Unattributed (whole − counted) | Samples without a rate | Renumbered discards |
|---|---:|---:|---:|---:|---:|---:|---:|
| Baseline | 33.8% | 2.9% | 0.2% | 41.6% | 4.8 points | 39 | 3 |
| With the short-lived load | 36.2% | 4.4% | 0.2% | 72.8% | **32.0 points** | 97 | 86 |

**What happened.** About a quarter of the machine (+31.2 points whole) became busy, but the validity measure (external) rose by 2.4
points. Two causes:

- a process that lives less than one 500 ms interval never has a rate, so it is never counted;
- renumbering discards the shifted instances of long-lived processes too.

**The repair's own evidence already shows it.** The committed dry run has about 8 points unattributed: the quiet check had 34.8% whole
against 26.8% counted, and the run beside the runs 45.0% against 37.1%.

**Why the rule cannot see it.** The specification lets no other source decide validity, and the whole-machine counter is recorded for
information only. So a quiet machine running a build or a scripted job of short processes passes the quiet check and its runs count as
valid. **C4DRR-M03.**

The bias makes runs slower, so it cannot create a false MET. It can certify a loaded machine as quiet. A false MISSED or STOP then
cannot be rerun, because the rerun rule requires an objective invalidation.

**C4DRR-M01: the §15.4 workload-class rule makes the representative class empty and leaves re-scans of high-novelty sources without a
class (specification defect; new text).**

- **Requirement:** §15.4 "Workload classes, by input parameters only" and its tie-break; D-53; PERF-01, PERF-14, PERF-15 (c), PERF-16
  by class.
- **Evidence (§5.5, measured here):**
  - The rows are nested upper bounds: representative d ≤ 25%, ρ ≤ 1%; stress d ≤ 60%, "as representative, but ρ ≤ 10%".
  - The tie-break takes "the hardest" row a cell fits.
  - Both representative matrix cells, F(·, 25%, system) and R(·) at 1% / 0.5% / 0.5%, fit both rows. The literal class of each is
    stress.
  - R(2M, 60%, data; 1%, 0.5%, 0.5%) fits no row: the stress re-scan row inherits the representative dictionary. So does any re-scan
    with δ or α above 5%. Both fall to "Informational: every cell outside the matrix".
- **Failure mode.**
  - A classifier coded from the text assigns PERF-01 to no cell and contradicts the matrix's labels.
  - The routine re-scan of a high-novelty source has no engine target and no Stop budget. That is exactly the "plausible difficult case
    simply excluded" the class design must prevent, and it contradicts D-53's statement that high-novelty real sources are bounded by
    PERF-14's engine target and the 5 s Stop.
  - Such a source is like the censused data volume, whose dictionary is about 1.2M names at 2M.
- **Required correction.**
  - State the classes as a total function of the parameters, as disjoint bands: for example, stress d in (25%, 60%] or model data, and
    ρ in (1%, 10%]. Or word the tie-break as "the least hard row whose every bound the cell meets; across parameters, the hardest".
  - Give a class to every R(n, d, m; ρ, δ, α), including re-scans of stress and worst-case first-save sources and δ or α above 5%.
  - Record in D-53 how the re-scan of a high-novelty source is bounded. Either add a stress cell such as R(2M, 60%, data; 1%, 0.5%,
    0.5%), or state as a product decision that such re-scans are bounded by the stop thresholds only.
- **Closure evidence:** revised §15.4 class table and tie-break, D-53 and the matrix; a boundary table like §5.5's that gives the matrix
  labels.

**C4DRR-M02: the key-range attribution passes an empty, truncated, corrupt or mismatched journal (specification and reference-tool
defect; new procedure).**

- **Requirement:** PERF-15 (a); §15.4 "key-range attribution"; TEST-P1; D-R4 ("`journal_ranges.py` is the reference or is ported").
- **Evidence (§7.6, measured here):** `journal_ranges.py` returns PASS for:
  - a 0-byte journal (what a copy taken after `COMMIT` gives);
  - a journal of zeros;
  - a corrupted header (0 records);
  - a checksum failure;
  - an image unlike the copy;
  - a half-truncated journal;
  - another run's database copy.
  Its verdict ignores its own integrity counts. §15.4 says the checksums are "verified" and the images "compared", but not that a
  failure invalidates the check.
- **Failure mode.** A TEST-P1 cell reports PERF-15 (a) PASS without evidence when its journal was copied at the wrong moment,
  truncated, or paired with the wrong database copy. The per-session negative control catches only a systematically broken copy or
  checker.
- **Required correction.**
  - **State in §15.4 when the attribution is invalid**, and that an invalid attribution fails the run's PERF-15 (a) check until it is
    re-analysed, never PASS:
    - an unparseable header or a truncated record;
    - a journal shorter than the pre-`COMMIT` handle length recorded for the run, or no records although the importer changed existing
      pages;
    - any checksum failure;
    - any original image unlike the copy;
    - any journalled page the walker cannot place;
    - a journal page size unlike the database's.
  - **Update the reference checker** to return a distinct INVALID outcome with a non-zero exit, and give it negative self-tests (the
    cases above).
- **Closure evidence:** revised §15.4 and TEST-P1 text; `journal_ranges.py` and its negative cases.

**C4DRR-M03: the PDH load source does not see short-lived processes, so the quiet check can certify a busy machine (benchmark-method
defect; new rule).**

- **Requirement:** §15.4 "Load source (the only one)", "Quiet check", "Validity"; D-53 ("benchmark validity rests on one load source").
- **Evidence (§10.4, measured here):**
  - Four concurrent CPU-bound processes of about 0.3 s each (261 in 24 s) raised the whole-machine counter by 31.2 points, but the
    external share by only 2.4.
  - The unattributed share rose from 4.8 to 32.0 points. Processes younger than one 500 ms interval have no rate and are skipped, and
    renumbering discards the shifted instances (86 samples).
  - The repair's own committed dry run shows about 8 points unattributed.
  - Only the number of discarded samples is recorded, never their CPU.
  - The specification forbids any other source from deciding validity.
- **Failure mode.**
  - A machine with near-zero external CPU plus a build or scripted job of short processes passes the quiet check (mean ≤ 5%, p95 ≤ 15%),
    and its runs are valid.
  - The gate session's timings are then a loaded machine's timings.
  - A false MISSED or STOP cannot be rerun, because there is no objective invalidation.
- **Required correction.**
  - Add a whole-machine condition from the same PDH query to the quiet check and to run validity, for example `_Total` less own (or
    less own and induced) within stated thresholds, or bound the unattributed share (whole − counted processes).
  - Record the CPU left unattributed, not only the number of discarded samples.
  - Keep the per-process classes for attributing induced load.
- **Closure evidence:** revised §15.4 method; `load_probe.py` with the cross-check; a churn case like §10.4's refused by the quiet check.
