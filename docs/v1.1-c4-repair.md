## 5. Errata and documentation corrections (C4-M15, C4-M16)

**A-09 and the figure 164 (C4-M15).** The implementation's numbers are correct: the provider assembly declares 150 P/Invokes (ImplMap rows) over 141 distinct entry points; the nine extra declarations are overloads of `sqlite3_config` (five declarations) and `sqlite3_db_config` (six) that share entry points. The specification's 164 is the number of distinct `sqlite3_[a-z0-9_]+` string
tokens in the provider file, which is 141 entry points plus 23 other identifiers (overload method names, type names such as `sqlite3_stmt`, and member references to the core API that are not P/Invokes). It is
not a different asset, a missed function-pointer import or an audit omission. This is an erratum for the figure, in documentation only; no requirement changes. The test keeps the exact 150/141 pin and its
message now points here (`LibrarySecurityAuditTests`).

**C4-M16 (a), the blocked benchmark documents.** `docs/benchmarks/library.md` and `library-raw.md` of the blocked implementation said, among other things, that two of six hosted runs were below 100k rows/s (one was), that
the "Phases (ms), best run" rows were the best run (the 2M row was run 1, 18,191 ms, while run 2 took 17.47 s), that the phase timings came from an uncommitted console log, that the workstation's machine,
CPU, SSD, Defender state and page size were stated (they were not), and omitted the quieter hosted green run of Q-07 (+18%, +20%, +19%). The documents are moved, unedited in substance, to
`docs/benchmarks/library-c4-blocked.md` and `library-c4-blocked-raw.md` with a banner that names the review's findings (C4-B01, C4-H02) and the superseding documents; the specification's Q-07 row says its figures are historical.

**(b)** `docs/v1.1-c4-implementation-evidence.md` called TEST-T4 "T4 (delete)"; T4 is the committed-but-unpublished (Damaged) snapshot test and T-DELETE is TEST-T3. The file carries a banner
that it is the record of the blocked implementation and is not edited otherwise.

**(c)** Size: both baselines are stated in `docs/release.md` (v1.0.0 130,947,561 bytes; C3 final 131,046,889 bytes; the repaired C4 133,650,249 bytes).

**(d)** `README.md` (the unpacked `e_sqlite3.dll`, the licence line, the History-database wording) and `.github/dependabot.yml` (the first-line comment) are corrected (`8fb52ff`); the mutant
record now carries a commit, a date and the baseline counts (`docs/evidence/c4-repair-mutants.md`).

**(e)** PERF-03 is not compared with its budget (C4-O09): unchanged, an observation; the repaired work does not touch scan-path cost.
