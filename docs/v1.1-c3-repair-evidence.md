## 7. Corrected wording (C3-M05)

Each correction is a single sentence in `docs/native-security-review.md` and `docs/v1.1-c3-implementation-evidence.md` (and the Q-19 and Q-02 context in the specification row where it appeared):

| Was | Now |
|---|---|
| SMB and mapped-drive results unqualified | "measured against a Windows SMB server on the same machine (loopback)"; Samba, a remote Windows server, a NAS and DFS listed as not measured |
| "both serials" for a share served from FAT32 | both serials for a share served from NTFS; only the 32-bit serial for one served from FAT32 (`FileIdInfo` is Win32 87 there) |

| "UDF image dismounted (Eject)" | `Dismount-DiskImage`, which takes no volume lock and is not what Eject does on a physical disc (documents and the script's report title) |
| "UDF (a real disc and a mounted image)" | a mounted image and a vendor's virtual CD drive; no physical disc |
| "is the one the specification accepts" and "the reviewer decides" | the outcome of the independent review (section 15) is cited; the C3 text is marked as an implementer record awaiting re-review |
| "never blocks a rename, a delete or a listing" | the source folder itself only; the ancestor effect stated beside it |

## 8. What the Windows runs found in the repair itself

The first hosted runs were red, and the failures were real defects in the repair, not flakes:

1. **Share ownership check** (my bug): the shares serve `M:\` and `O:\` (the virtual volumes), not a folder inside the scratch root, so the first version of the teardown refused to remove them and the real teardown left two shares behind. The check now compares the served path with the volume the manifest names for that share (`ntfsA` for `SiEvidenceA`, `fat32` for `SiEvidenceB`); fixtures 2.10 and 2.11 use those shapes and mutant S5 covers it.
2. **Compiled reflection rule scope**: the rule flagged generated WPF code in the App (section 4). Narrowed to Core and History.
3. **PowerShell 7.6 error text** is wrapped and has a `|`/`~` gutter, which broke two fixture message matches; the fixtures strip it.
4. Two workflow steps ended with the exit code of a native command that is expected to be non-zero; they now end with `exit 0`.

The ordinary CI run also failed once on `ShellParityTests.The_binding_diagnostics_are_live` (a WPF binding-diagnostics test in code this repair does not touch); it passed on the re-run of the same tree
(one confirming re-run, as the process allows). It is not a repair finding but it is recorded.
