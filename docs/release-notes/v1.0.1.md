# StorageInventory v1.0.1

A patch release that fixes one problem in v1.0.0. Nothing else changes: scanning, reports, safety checks, link
handling and cancellation are exactly as in v1.0.0.

## Fixed

- **The Windows application could open as a blank, white window on some systems.** The window, its controls and the
  scanner were all there, but nothing usable was visible.

  **Cause.** v1.0.0 used the experimental Fluent theme of WPF (.NET's Windows UI framework) with its *Mica* window
  backdrop. On Windows 11 22H2 and later, that backdrop makes the window's own background transparent and leaves
  Windows' compositor (the Desktop Window Manager) to draw the Mica material behind the content. StorageInventory
  therefore painted no background of its own. Where the compositor did not fill that area, which depends on the graphics
  hardware and driver, the window showed an unpainted white surface; in the dark theme all the text is white, so the
  whole window looked blank. (The virtual test machines used for this release drew the backdrop correctly, so the blank
  window itself could not be reproduced on them. The new tests instead prove that v1.0.0's window depended on that
  backdrop and that v1.0.1's does not.)

  **Fix.** v1.0.1 switches the Mica backdrop off (with WPF's documented switch for that purpose), so the window paints
  its own solid light or dark background, as v1.0.0 already did on Windows 10. The look is otherwise unchanged; on
  Windows 11 there is no subtle wallpaper tint behind the window any more, and text is drawn with ClearType again.

## Testing

v1.0.0 passed its UI Automation smoke test while the window could be blank: UI Automation sees controls whether or not
they are drawn. v1.0.1 adds checks that look at pixels:

- an integration test that the window paints an opaque background of its own, in the light and the dark theme;
- a visual startup gate for the published executable (`tests/smoke/Test-VisibleStartup.ps1`, also run by CI), which
  checks the window on screen, reads the window's own surface without the compositor's backdrop, and requires every
  landmark to stay visible over white and over black. It fails for the v1.0.0 executable and passes for v1.0.1.

Results for the executable above, on a GitHub-hosted Windows Server 2025 x64 runner (virtual display adapter,
1024×768, 96 DPI), Release configuration:

- Unit tests 55 pass / 0 fail / 0 skip; integration tests 87 / 0 / 7 (the skips need benchmark trees or 8.3 names the
  runner doesn't have). The new window-background test fails on v1.0.0's code and passes on v1.0.1's.
- PowerShell reference suite: 108 pass / 0 fail / 3 skip on Windows PowerShell 5.1 and on PowerShell 7.6.6.
- Release smoke test, with the exe copied outside the repository and started with no `DOTNET_ROOT`: 46/46 pass. It
  covers a complete scan with three CSV reports, opening the report folder, a 250,000-file scan cancelled with no
  report file left open, a clean exit, and the setup and results screens checked visually.
- Visual startup gate: cold start (extraction folder cleared) in the light and the dark theme 50/50 pass; warm relaunch
  25/25 pass. The same gate run against the original v1.0.0 executable: 10 failures.
- During the investigation the fix was also seen painting its own opaque background on Windows Server 2022 x64 and
  on Windows 11 25H2 ARM64 (x64 emulation).
- Not tested: physical graphics hardware. The hosted machines have none, so the blank window itself could not be
  reproduced on them.
