# StorageInventory v1.0.0

The first public release of StorageInventory: a **read-only storage inventory for Windows**. Point it at a drive or
folder, and it writes a complete, sortable record of every file and folder, with sizes, dates and attributes, to CSV
reports you can keep. It never opens, changes, moves or deletes your files.

## Highlights

- **Native Windows app** with a pre-flight safety check, live progress, safe cancellation and a results screen:
  largest folders, largest files, file types and errors.
- **Three CSV reports per scan** (Files, Folders, ScanErrors) plus an optional Excel workbook that needs no Excel
  installation. Every report is a new, uniquely named file; nothing is ever overwritten.
- **Honest outcomes:** *Complete*, *Finished but incomplete* (some folders couldn't be read, so totals are lower
  bounds), *Cancelled* or *Failed*. A partial scan never looks complete.
- **Link-safe:** junctions, symbolic links, mount points and cloud placeholders are listed and never followed.
- **No administrator rights, no installation, no network activity of its own, no telemetry.**
- **One self-contained executable:** no .NET installation needed.

## How to use it

1. Run `StorageInventory.exe`.
2. Choose the folder or drive to scan, and a report folder **outside** it.
3. When the pre-flight panel says **READY TO SCAN**, start the scan.
4. Read the outcome, browse the tabs, and open the reports.

## Good to know

- **Reports contain private information:** file names, folder structure, sizes and timestamps. Review them before
  sharing, and note that a report folder inside OneDrive (or another synced folder) will be uploaded by that service.
- **What is written:** only the report files, in the report folder you chose (plus a temporary file during sorting,
  removed afterwards). The single-file executable's .NET host also unpacks WPF's native libraries to
  `%TEMP%\.net\StorageInventory\` on first run.
- **Known limitations:**
  - A folder swapped for a link during a scan can still be followed in a very small window (read-only).
  - `\\localhost\C$`-style aliases are caught at run time rather than up front.
  - Hard links are counted per link, and sizes are file lengths rather than space on disk.
  - Mount points use the same code path as the tested junctions and symbolic links, but aren't created by the tests.
