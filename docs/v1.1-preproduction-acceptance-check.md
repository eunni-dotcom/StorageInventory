## 3. G0F-H01 verdict

**Classification: CLOSED.** No path in the specified rule emits Added or Missing for a comparison whose listing
visibility is unverified, in either direction. One premise of the rule is not yet written for the visibility axis
(G0E-M03); it cannot take effect before Q-23 lists a class, so it does not reopen the finding.

**The rule as written.** DIFF-14 [SPEC 1730-1747]: `V = Complete` only when **both** snapshots were captured through a
local volume whose recorded filesystem name is on the complete-listing list, which is empty by default and filled in C7
from Q-23's evidence; every network capture (a UNC path or a mapped letter) is `Unverified`, from either snapshot.
DIFF-12 [SPEC 1776]: `ProvenAbsent_N(p) ⇔ V = Complete and (NI_N(p) or (A = Verified and KB_N(p)))`, and Added uses the
same definition with O and N exchanged. DIFF-11 step 2.2 [SPEC 1757-1763]: case-fold matching only when `V = Complete`.
Restated in the reason table (`VisibilityUnverified`, [SPEC 1789]), §12.3 and §12.4 notes [SPEC 1855-1858], L-DIFF3
[SPEC 1942-1955], DIFF-P13 [SPEC 2093-2095], REQ-06, ID-09, §13.2 and UI-04.

| Transition, visibility `Unverified` | Result | Rows |
|---|---|---|
| Visible in the older scan, not in the newer (deleted, hidden by access-based enumeration, ACL changed, another account) | Unknown (Newer, `VisibilityUnverified`), the hidden folder's subtree included; never Missing | T47, T50, T54 |
| Not visible in the older scan, visible in the newer | Unknown (Older, `VisibilityUnverified`); never Added | T55 |
| The same exact path positively observed in both | Changed, Unchanged or Unknown (ChangeIndeterminate) by the normal rules; folders Present | T56, DIFF-P13 |
| Case-only rename; type change at the same exact name | Two Unknown items; no case-fold match | T51; §12.3 note |

| Source | Capability | Added or Missing possible? |
|---|---|---|
| SMB share, DFS namespace path, access-based enumeration, NAS "hide unreadable" policies | Network capture, `V = Unverified` | No (T47, T50, T51, T54, T55) |
| Permissions changed between scans; scans under different accounts | Network: as above. Local: a folder the account cannot list is reported Unreadable, never as an empty listing (v1 lists with `IgnoreInaccessible = false`) | No on network; locally the Q-23 premise |
| Mapped letter, including one backed by a network provider that reports a remote drive | Network ("a UNC path or a mapped letter", [SPEC 1737]) | No |
| Third-party local filesystem that reports its own name | Not on the list, `V = Unverified` (capability table [SPEC 1050]) | No |
| Third-party local filesystem that reports an in-box name, or a filter that hides entries on an in-box filesystem | Treated as that class | Only after Q-23 lists the class: G0E-M03 |
| NTFS, ReFS, FAT family, UDF (local) | `Complete` only once Q-23 passes for the class; `Unverified` until then | Not before that evidence |

**Product limitation: coherent.** L-DIFF3 states that v1.1 reports positively observed network history (exact paths in
both scans, Changed and Unchanged, sizes, totals of what the account could see) and makes no authoritative claim about
creation or deletion where namespace visibility cannot be proven; §13.2 and §14.4 show "Not reported for this location"
instead of an empty count. With the default empty list no comparison, local or network, reports Added or Missing until
C7 lists a class from evidence; C7 lists NTFS from CI evidence, and an NTFS listing that omits an entry stops C7 as a
product question [SPEC 3052-3053]. That is a conservative and consistent product state.

**Why G0E-M03 is medium, not high.** It needs a driver that reports an in-box filesystem name (or a filter that hides
entries on a genuine one); it cannot occur with the default empty list; the same trust in the reported name is already
accepted for matching (NAME-04, adopted after G0F-O08); and a hiding filter on a genuine volume defeats any listing-based
proof, so the correction is to state the premise and gate the listing, not to change the rule.

Related observations: G0E-O02 (banner wording), G0E-O03 (the "source folder was recreated" notice).

## 5. G0-B01 regression verdict

**Classification: CLOSED; no regression.** The corrections add the constructed start-up state and transitions into
Faulted; neither reaches Idle, Observing or Mutating from a state the `121358c` table did not allow.

| Sequence | Result under `1673358` |
|---|---|
| Save overlap: scan A completes; save begins; scan B requested | Observing(A) hands over to Save(A) atomically at P4 (OBS-10); the interlock is never Idle in between, so B is refused (O28): no report file, no attempt. B becomes possible only when Save(A) has committed or rolled back, written its outcome and closed the writer and the spool |
| Deletion overlap: deletion begins; scan requested | Delete lease held; refused (O28). A deletion during a window is refused (O29) |
| Observation first: scan begins; Library mutation requested | Observing(r) grants no mutation lease (OBS-02, OBS-07); refused (O29) |
| Recovery (hot-journal rollback, T-RECOVER) | Inside the start-up Open lease, a Retry's Open lease, or (new) the capture's Prepare or Create lease through LIB-07 step 4; always before any window, since the hand-off to Observing follows the writer's close (OBS-10) |
| Set-aside | SetAside lease, lock first; refused during a window |
| Start-up and open | Constructed in Mutating(Open); no Idle moment before the open ends (OBS-14); a scan request is refused and starts nothing |
| Open-instead-of-create (new path) | Runs inside the same Prepare or Create lease; adds no state and no transition |
| Catastrophic transition | Faulted grants nothing and has no exit; closing writes nothing; an open transaction is rolled back by disposal or by SQLite at the next start, when this process can no longer observe |
| Stop saving, a failed import, closing during save | The lease ends after rollback and outcome; the next scan waits for Idle |
| A stale or foreign lease | OBS-15 can only refuse, never grant; a failed check makes the interlock more restrictive (Faulted) |
