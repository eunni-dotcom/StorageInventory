## 3. C4R-M01: no bound on the stretch between two checks inside one big folder

### 3.1 The defect, as the review measured it and as reproduced here

`SnapshotImporter.InsertFiles` interned every name of a folder before it inserted the folder's rows, and the 4,096-row counter advanced only for
observation rows, so the stretch held no look at the lease, the save token or the space guard. The review measured one folder of N new names: 100,000
names, 0.68 s between two checks and 0.47 s from a cancellation to the return; 200,000 names, 1.28 s and 1.08 s (CAN-01d and CAN-03 allow 0.5 s).
The reproduction is the mutant `C4F-A01` (the repaired importer with its accounting removed from the interning): the new large-folder tests fail on it
for the intended reason (section 3.4).

### 3.2 The repair (`SnapshotImporter`, `TokenChecker`)

* **Rows of any table.** IMP-11 (3) and CAN-01d say "every 4,096 inserted rows **of any table**". The `name` and `folder_path` inserts now count: every
  name goes through one helper (`Intern`) that adds the rows the cache actually inserted (a name new to the source's dictionary is one row of `name`;
  a name found in the cache or the dictionary is none), and the folder phase adds the folder-path row when the path is new. The check is the same
  primitive as before (lease, save token, space guard with its exact inputs), at exactly every 4,096th row. `SpaceCheck.RowsInserted` is the count of
  rows of any table.
* **Time bound (CAN-03), deterministic.** A 4,096-row cadence does not prove 0.5 s when a row is slow or when work inserts nothing (a name looked up in a
  source that already has it: no row at all). The importer therefore also counts *units of work* (a row inserted, a name looked up); after every 64
  units it reads the clock, and when 100 ms have passed since the last look at the token it looks at the lease and the token (not at the space guard,
  whose cadence is rows: growth is driven by rows). 64 units cost one clock reading (tens of nanoseconds) against microseconds per unit, so there
  is no per-row clock call; a unit that takes a few milliseconds (a stalled disk) still keeps the look within about 64 units of the 100 ms. The bound
  is `ClockPoll` x unit cost + `MaxLookGap`, far inside the 0.5 s budget, and the clock is a seam (`ImportOptions.Clock`, `TokenChecker`'s clock) so the bound is tested
  without waiting.
* **No reset at a folder boundary.** Both counters (`Rows`/`NextGuard`, `Work`) live in the import's state object and no loop resets them; a test with
  400 small folders pins it (a counter that restarted at each folder never reaches its threshold).
* **Every loop that inserts or looks up is accounted:** name interning (files and folders), folder-path and folder rows, file rows (the batches of 8
  and the single rows), scan-error rows and extension-total rows. The verification keeps its own observation cadence (token between queries, every
  65,536 rows of a streamed query, the engine's progress callback every 20,000 VM steps), unchanged.
* **The IMP-11 inputs.** The page size is read at *every* check, as IMP-11 states ("`P`, `S` and `L` at every check"); the earlier cache after `BEGIN`
  made a later failing read impossible to observe and is removed (section 4).
* **Harness consequence.** A check's row count now includes dictionary rows, so TEST-P1's cancel point 1 ("right after a row check at or after 95% of
  the rows") reads file progress (95% of the files, `OnFileRows`): the dictionary rows and folder rows all precede the file rows, so from there at least
  95% of every row has been inserted.
* **Cost.** At 2M files the number of checks rises from about 610 (the specification's estimate, from observation rows alone) to about 850 to 1,300 (rows
  of any table: files, folders, folder paths and new names; an estimate from the row counts, not a measurement), each a metadata call, two pragma reads
  and two handle lengths. That is well under 1% of a 20 s to 45 s import and is conservative against PERF-01 and PERF-14. It is a consequence of the
  accepted text ("any table"), not a change to it.

### 3.3 What the change does not claim

A single call into the engine is not interruptible by the importer: a statement waiting in the busy handler (`busy_timeout` 5,000 ms) or a cache
spill's write. Under the exclusive gate and the writer lock no StorageInventory connection can hold a SQLite lock, so the busy handler has nothing to
wait for; an external program that locks the file is environmental and not tested. Reading a folder's records from the spool (C5) carries its own
cadence (CAN-01d: the token every 64 MiB of spool); the abstract `ISnapshotRowSource` of C4 has none.

## 4. C4R-M02: TEST-L9's "exact inputs" and "an unreadable `page_count`"

### 4.1 The defect

No test made `PRAGMA page_count` or `page_size` fail; the periodic checks' inputs were compared only with the record's own fields; `Λ` had no 64-bit
test (reviewer mutants RV-10 no clamp, RV-14 `IsUnreadable` without `SqliteException`, and the importer agent's "page_count read as 0", "main length 0 at periodic
checks" and "page_count frozen at periodic checks" survived).

### 4.2 The repair

* **A seam for the engine-side reads**, as `FileLengths` is for the lengths: `ImportOptions.OnEngineInput` (null in production) sees each value just after it is
  read (`page_count`, `page_size`) with the check's kind, may replace it, and what it throws is an unreadable input, exactly as an exception from the engine
  would be. It is a filter after the read, not a capture of the writer, so it opens no path to the lease.
* **`SnapshotImporter.PendingGrowth(pageCount, pageSize, mainLength)`**, a pure function: `Λ = max(0, page_count x page size - main)` in 64 bits, `checked`, and
  out-of-range inputs (a negative count or length, a page size of 0 or less, an overflowing product) throw, which the importer reads as an unreadable input: fail closed.
* **Both pragma reads at every check** (section 3.2): `page_size` is no longer cached, so it can fail at `BEGIN`, at a periodic check and at the final check like `page_count`.

## 5. C4R-M03: a cancellation that publishes is a measured miss, never a replaced run

Full account (reproduction, classification table, judgement calls): `docs/evidence/c4-repair-followup/m34-session-tooling-notes.md`. In short:

* **Reproduced before the fix**: a cancel run whose save published exits 3 (`missing cancel.rollback`); so do a save that failed at `BEGIN` (`imp11.checks holds fewer than two checks`) and a cancel point that
  was never reached; the Python judge reads exit 3 as "the harness child failed", status `invalid`, which `needs_run` replaces. An attributed run whose save failed was handed to the checker (INVALID, replaced).
* **Classification** of every cancellation-gate run: (i) *expected cancellation* (requested, rolled back, asserted; judged on time); (ii) *miss* (requested and the save published or failed, or the rollback did not hold,
  or the point was never reached): a **valid, measured run, kept, never replaced**, MISSED on PERF-15 (c) and PERF-16's engine part, and STOP when the measured request-to-return time is above 1.5x the budget; (iii) *invalid
  harness or evidence* (a child that died or could not start, an uninterpretable record, the load rule, a failed round): replaceable only under the accepted rules (at most five more attempts, then NOT MEASURED).
* **Effect on the gate**: a miss never reads MET, blocks acceptance, and stays in the session record with its reason (also when the load rule invalidates the run: what it showed is kept in its row and named in the report).
* **Exit codes** (`perf_session.py`): 0 done, 1 negative control did not FAIL, 2 refused or usage, 3 quiet check before the session failed, 4 aborted by an `OSError`, 5 unhandled exception (it used to exit 1, the code of
  "control failed": C4R-O12). The harness child exits 0 for any interpretable record and 3 only for one that cannot be interpreted.
* **Judgement calls to confirm** (each one small edit to undo): the STOP reading for a slow miss (the specification defines the stop threshold on time and is silent on an ignored cancellation); a never-reached cancel point is a valid
  miss, not an invalid run.
* **Squash note**: the work stream's red reproduction commit and its two fix commits (`9725516`, `480ad5a`, `b0671df` on `v1.1/c4-fixes-m34`) are one commit here (`36f2cdb`); its mutant runner and notes are `756c4be` and `6366fc5`.
  The notes name the original SHAs.

## 6. C4R-M04: an attempt is run once, and the negative control is part of the result

* **Reproduced before the fix**: a refused directory run again exits 0 with `refused.json` still present and the report saying REFUSED; an aborted directory run again produced 20 judged runs of 13 distinct ids with repeated `order`
  values; a negative control that PASSED gave `session.json: TEST-P1 FAILED` but the report said `Status: complete` with PERF-15 (a) MET and `outcome` exited 0; Ctrl-C was not recorded.
* **Model**: a session directory is an attempt and is run once (`run` refuses a directory that holds `refused.json`, `aborted.json`, `session.json`, a raw table or a log, before touching it). A retry is a **new declaration** that names
  the earlier attempt (`declare --gate --supersedes <id> --reason ...`), which must be the latest gate session of the binary and must have been invalidated by the rules, derived from its files (refused, aborted, never completed,
  negative control did not FAIL, cells NOT MEASURED); a validly completed session cannot be superseded. Refused and aborted attempts keep full records (id, gate flag, manifest hash, declared configuration, evidence pointers,
  reason or error, and for a refusal the quiet-check summary and its raw 120 collections); `perf_session.py attempts` lists every attempt and the report covers refused, aborted and incomplete ones in full.
* **Negative control**: `gate_model.judge_control` (both variants must give a valid FAIL; a PASS is final and is never cured or replaced); `rebuild`, `finish`, `outcome`, `attempts` and the report read it and mark the session and
  PERF-15 (a) `TEST-P1 FAILED`.
* **Process caveats** (stated in the notes): a Ctrl-C is recorded as an abort, which consumes the attempt and makes it supersedable (the aborted attempt stays in the evidence and the report; whether that is acceptable is a
  process decision); `--supersedes` is tighter than before (an invalidation the files cannot show cannot be declared with this tool); manifest integrity (C4R-O12) is unchanged.

## 7. C4R-M05: the A-25 audit

Full account: `docs/evidence/c4-repair-followup/m05-audit-notes.md`. In short:

* **The reviewer's mutants, reproduced first** (the exact edits are in the notes): the generic-arity alias (`RvH<T>` called under the lease, an `internal object? RvH(string)` that executes on the writer) and the retained delegate
  (`_retained = sql => Scalar(lease, sql)` set in `Configure`, run by a lease-less `Poke`; and the `LibraryStore.CreateEmptyDatabase(lease)` variant) all passed the audit (51 of 51), and **survive the earlier audit at `7b41022`** (17 of
  20 genuine mutants did).
* **Method identity**: one function (`IlAudit.MethodKey`) builds the key of a definition, of a call and of the dispatch tables from the declaring type, name, **generic arity**, the exact parameter signature (generic arguments,
  by-reference, pointer, array rank, function-pointer signature, custom modifiers) and, for conversion operators, the return type; the metadata token is kept and same-assembly calls resolve by it. **Two non-generated methods that share a
  key are an audit failure** (`A25a/ambiguous-method-identity`); none exists in the product.
* **Closures**: a lambda, local function or display-class closure that is bound to a delegate, takes no lease and reaches a mutation is an *authority closure*; the delegate is tainted from its `newobj` and must not reach a sink (a
  static, an array element, an instance field of any object but the one under construction, a return, a throw, a pointer store, code the audit cannot read, or a callee whose summary lets it escape): `A25a/closure-escapes`. Interface,
  virtual and delegate calls are judged against every implementer or bound method; iterators that reach a mutation are rejected; no compiler-generated method is exempt. **Fail closed**: a body the simulation cannot read, an analysis
  that does not converge or exceeds its budget is `A25a/unresolved-closure-flow`. The Library's accepted shape (`DelegateQueryRunner` built from two lease-capturing closures in `SnapshotImporter.Execute` and
  `LibrarySession.CheckIdentity`, handed to `SnapshotVerifier.Verify`) passes because the analysis proves it; the four authority closures of the product are pinned by a test. Production code was not changed.
* **Run-time half** (`LeaseRuntimeAbuseTests`, 7 new): a delegate that captured the opener's lease works while the lease is current for every one of the writer's 20 operations, and throws `LeaseViolationException` before any I/O
  (the interlock Faulted, no statement, no BEGIN/COMMIT/ROLLBACK, no file changed) after the lease was disposed, handed off or replaced by a newer lease of the same kind, and when a lease-taking delegate is run by a lease-less
  caller with a default, a foreign or a stale lease.
* **Limits stated by the work** (not hidden): an escape analysis by value flow, not a whole-program proof; a delegate that is merely *invoked* is judged by the frozen wording; the BCL is never a safe sink (`Task.Run`, events,
  collections and `DynamicInvoke` are rejected even where harmless); init-only setters and object initializers that receive an authority closure are rejected; arguments of a delegate invocation are judged coarsely; iterators are
  rejected rather than followed; adding any authority closure fails the pin until a reviewer extends it. C4R-O06's other edges (lease producers, part (c) being name-based, `LibraryStore`'s own methods) are unchanged.
