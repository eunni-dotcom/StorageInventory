upper and lower case. `K_spec` is NAME-03 (NFD first, then the class representative per code point); `K_fix` folds per

**R2: real up-case tables [DOC].** ntfs-3g's `ntfs_upcase_table_build` (Windows XP table plus the Vista, 7 and 8
revisions, with the MD5 of each Windows `$UpCase`) contains no entry for U+0345, so NTFS maps it to itself. Linux
`fs/exfat/nls.c` `uni_def_upcase` (the exFAT default table) maps U+0345 to U+0345.

**R3: hot-journal recovery when the first statement sets TRUNCATE [PROBE].** A database in TRUNCATE mode; a child
process updates existing pages and inserts rows in one transaction with a small cache, then exits without committing.
The recovering connection's **first** statement is `PRAGMA journal_mode=truncate`:

```
B after crash: {'library.sqlite3': 6598656, 'library.sqlite3-journal': 1125080}
B pragma result: ('truncate',)
B after first stmt (pragma): {'library.sqlite3': 1118208}        <- journal DELETED, not truncated
B rows: (10000, 0)                                                  <- recovery correct
```

Preparing the pragma reads the schema, which rolls back the hot journal in the connection's default `DELETE` mode
before the pragma takes effect.

**R4: SQLite on Windows [DOC].** `pager.c` `pager_unlock`: when dropping the database lock, the journal handle is
closed only if the VFS lacks `SQLITE_IOCAP_UNDELETABLE_WHEN_OPEN` or the journal mode is not PERSIST/TRUNCATE.
`os_win.c` `winDeviceCharacteristics` always returns `SQLITE_IOCAP_UNDELETABLE_WHEN_OPEN`, so on Windows a TRUNCATE-mode
connection keeps `-journal` open between transactions. `winOpen` uses `FILE_SHARE_READ | FILE_SHARE_WRITE` (no
`FILE_SHARE_DELETE`). `hasHotJournal` deletes a journal beside a zero-page database (`nPage==0 && !jrnlOpen`); a
read-only connection facing a hot journal gets `SQLITE_READONLY_ROLLBACK`. `vdbesort.c` sets no spill threshold when
`sqlite3TempInMemory(db)` is true, and `pager.c` keeps sub-journals in memory when `subjInMemory` is set: with
`temp_store=MEMORY` neither the sorter nor statement journals create temporary files.

**R5: v1 App and scanner [SRC].** `MainViewModel.Scanning.cs:36` enables `NewScanCommand` whenever
`Stage == AppStage.Results`. `InventoryScanner.cs:50` enumerates `validation.RootFullPath` (the normalised entered
path), not the canonical path.

**R6: traceability [PROBE].** A script over the spec: 24 internal links, 0 broken (GitHub anchors); 72 `TEST-` IDs
defined in §18.1 (§23 says 66: G0-O05), none referenced but undefined; T1 to T48, O1 to O27, Q-01 to Q-21 and D-01 to
D-49 all present; every REQ-01 to REQ-16 and every SEC ID appears in §18.2; the only normative IDs absent from §18.2
are deferred ones (LIB-11, SREQ-04 to SREQ-10).

| **Affects** | NAME-03 (920), NAME-04 (921), D-38, §12.2 (width premise), Q-14 (2800), TEST-D6, §12.11 |
| **Evidence** | [SPEC] NAME-03 applies `NormalizeD` first and then maps code point by code point. [DOC R2] The NTFS default up-case table (as reproduced by ntfs-3g through Windows 8) and the exFAT default table both map U+0345 to itself, so NTFS and exFAT with default tables are not affected. SMB servers define their own folds (§8.1) and are a supported capability in NAME-04's table *(which fold each uses: not verified)*. ## 6. Missing/Unknown audit

### 6.1 The rule, re-derived

For an unmatched O item `p` with deepest aligned proper ancestor pair `(a_O, a_N)`, child `c` on the path and type `T`:
`p` is Missing iff `a_N` is Listed (status Ok) and `a_N` has **no** child of type `T` with `K(x) = K(c)`, matched or
not (DIFF-12). Added is symmetric.

The argument was re-derived independently and holds, given one premise: every name pair that a filesystem treats as
the same name at listing time has equal `K`.

1. An exact match (same exact name, same type) is always the entry at `c`'s position, in any directory.
2. A case-fold match needs two Listed parents and a single same-type member of the key class on each side, counting
   matched members. Any entry at `c`'s position in N has key `K(c)` and type `T`, so it is that single member, or
   `c`'s position holds no type-`T` entry and `c` with its subtree is truly absent. A match with a folder that is not
   the true position can only turn Missing and Added into Present or Unchanged (L-DIFF1), never the reverse.
3. With `a_N` the true position (or `a_O`'s position truly absent), a complete listing with no same-key, same-type
   child proves that nothing of type `T` existed at `c`'s position when `a_N` was listed.
4. Each direction uses its own snapshot's directory rules, so a change of per-directory case sensitivity between
   the scans (T41) is handled without knowing the flag.

The premise is where the repaired design is still weak (G0-M02).

### 6.3 Width and breadth of `K`, and per-filesystem case behaviour

- **Not too broad.** `K` folds case, canonical-equivalent forms and a few special classes (for example `ſ`, the Kelvin
  and Ångström signs, dotless and dotted i). Real names rarely collide under it beyond case variants and NFC/NFD
  pairs. Extra breadth only moves results to Unknown (NameVariantPresent) or produces spelling-only matches under two
  complete listings (L-DIFF1). No unrelated names are merged in a way that yields Missing or Added.
- **Not proven wide enough.** See G0-M02: normalising before folding can narrow `K`, and OS-provided casing data can
  vary by Windows build.
- **Case behaviour per filesystem and per folder.** The rule never needs to know it, which is the right design for v1
  data (no per-directory flag is collected, Q-16). The capability table (NAME-04) lists NTFS default and
  case-sensitive folders, FAT family, UDF and SMB correctly. Q-14's census verifies NTFS in CI and exFAT and FAT32
  manually; SMB is not covered by any experiment (G0-M02 asks for a stated residual).

### 6.4 Oracle, world-model and property tests

- TEST-D2's oracle shares only the observation types and `K` with the engine and implements §12.2 literally: suitable,
  with the caveat that a defect in `K` is shared by both and invisible to the comparison. TEST-D6 is the only guard
  for `K` and must include the reordering case (G0-M02).
- TEST-D5 runs the **production engine** against generated worlds with per-directory case sensitivity and changes to
  it, with an exact-key control that must fail: meaningful. Its fold and names should include multi-character
  combining sequences once `K` is corrected.
- DIFF-P3 (monotonicity) was checked by hand for lowering a parent to Partial, a child to Unreadable and a folder to a
  link: matches can only be lost, never gained, and every item that loses one becomes Unknown. Holds.

### 6.5 Verdict

Unknown/Missing is mechanically sound **as a rule**. Its premise, the width of `K`, is not yet established by
construction (G0-M02). With RR-03 applied, the invariant is mechanical end to end.

  (public surface) guard it. C1 can stay behaviour-preserving.
- **File records.** Folder index, exact UTF-16 name, size, three tick values, attributes; the sequence is the record's
  position. Everything `file_obs` needs; the extension is recomputed. Complete against `FileInventoryRecord`.
- **Folder records.** Emitted only after aggregation and `Verify` (SINK-08); there are **no provisional folder
  records** in the spool, so nothing can be mistaken for final completeness. Complete against
  `FolderInventoryRecord` except derived or display-only fields (`FullPath`, depth, percentages,
  `LargestFileRelativePath`, which v1's browsing does not show).
- **Error records.** Type, path as v1 reports it, message; root-relative paths are computed at import from the
  scan's root. Complete.
- **Aggregation and ordering.** Ascending folder index with `parentIndex < index`; file runs contiguous per folder
  with interleaved errors allowed (SINK-03). The run index makes key-ordered import possible.
- **Attempt token.** The capture token in the header must equal the in-memory token and the attempt's
  `capture_token` (SPOOL-06, IMP-05(d)). Correct.
- **Integrity.** Trailer counts and totals checked at P5; the SHA-256 needs a defined verification pass (G0-M05).
- **Versioning.** Magic `SISPOOL1`, a format number, `spool_format` recorded per snapshot. Adequate for a private
  format.
- **No public API.** `IScanObserver`, the fan-out and the spool types are internal (SINK-09, A-13), with TEST-O5
  guarding Core's public surface (re-baselined once in C5, G0-O07). C1 creates no public 1.2 integration API.

Rollback journal in `TRUNCATE` mode is the right choice for this workload, confirmed independently: reads write no
file (E-2; the pager does not touch the journal for reads unless it is hot); committed data always lives in the main
file; an appending import journals almost nothing (E-5 `dbOrigSize`); there is no checkpoint and no close-time side

### 11.2 Can an invalid snapshot become eligible?

One path was found: G0-M03 (a SUBST or mapped letter re-pointed during a scan), which TEST-I5 would catch before C5 can pass, and which RR-04 closes. No other path exists. Publication requires P5 (Finished, sealed spool matching the result, F1 = F2, E0 = E1 = E2 = E3)
and IMP-05's checks inside the one transaction; `PublishedSnapshotId` comes only from committed rows with
`state = 2`; every comparison re-verifies sealed totals (DIFF-10); every open checks the committed state (LIB-08 step
7). G0-B01 loses a valid capture or pollutes a Save-off scan's reports; it cannot publish an invalid snapshot, because
T0 passes through the gate and CONC-07 serialises captures.

### 11.3 Capacity and performance honesty

- **Measured versus projected.** §15.1 labels its Windows figures as a proxy engine (`winsqlite3` 3.51.1, WAL, TEXT
  names, written alone, insertion order not recorded, one and two snapshots) and the Linux figures as relative only.
  §15.2 labels every multi-snapshot figure as projected. The 10, 50 and 100-snapshot sizes are nowhere presented as
  measured, apart from one wording slip (G0-O04).
- **Future targets.** PERF-01 to PERF-16 are budgets with a confirming gate; stop conditions exist for the engine
  (§15.4).
- **Re-evaluation of full snapshots.** CAP-01 to CAP-05 are observable locally and proportionate; delta storage is not
  required without evidence (D-07). Agreed.
- **Over-generalisation.** PERF-15, PERF-16, CAN-03 and IMP-09 extrapolate from a single-table probe (G0-O03).
