## 4. Design as built

**Interlock (D-51, OBS-\*).** One monitor-protected field group, never held across I/O: `Idle`, `Mutating(kind, owner)`, `Observing`, `Faulted`
(terminal). Leases are `readonly struct`s carrying the owner interlock, a never-reused id and the kind; only the interlock constructs them
(A-25 c). The session starts `Mutating(Open)` (the start-up lease) and refuses everything until it ends cleanly. Hand-offs Prepare to
Observing to Save keep the window's mutation epoch (OBS-04a). Resources opened under a lease are counted; a lease that ends with a resource
open or after a class C failure faults the interlock. Every Library operation checks its lease (owner, id, kind, state) **before any I/O**
(OBS-15): at writer open, BEGIN, each statement, every 16,384 rows and before COMMIT; a failed check faults the session's interlock.

**Library files.** `library.lock` is opened `FileShare.None` for the process lifetime (cross-process writer lock, LIB-\*), created lock-first
with `CreateNew`; an in-process reader/writer gate (CONC-06) serves writers in order and cancels readers when a writer takes the gate. The
header pre-check reads 100 bytes with no SQLite and refuses anything that is not a rollback-journal SQLite 3 file with the Library's
application id before SQLite opens it (SEC-32). Nine states: NotCreated, Available, Missing, LeftoverFiles, Unavailable, InUse, Incompatible,
NotALibrary, Damaged. Creation re-derives the state under the lock and never overwrites an existing Library. Set-aside is the only rename.

**Schema 1.** Twenty objects; the schema fingerprint is SHA-256 over the sorted `sqlite_schema` rows (CRLF-normalised):
`8f96f561b6f811559bf56fe26322ae43e6835ea4f61c1c15df5200078b773457` (frozen in a test). Stable codes are explicit-switch tables
(`StableCodes`), independent of C# enum values; an unknown stored code is a `LibraryDataException` (class A), never a crash.
PRAGMAs: `journal_mode=TRUNCATE`, `synchronous=FULL`, `foreign_keys=ON`, `trusted_schema=OFF`, `temp_store=MEMORY`, `busy_timeout=5000`,
`locking_mode=NORMAL`; the import raises `cache_size` to 64 MiB. No VACUUM, ATTACH, WAL or extension loading (A-06, A-07, A-22).

**Import (T-IMPORT).** One `BEGIN IMMEDIATE`. Names interned through a bounded two-generation cache; folder paths interned per source; file rows
inserted in key order in batches of 8; invariants 1 to 12 verified **inside** the transaction; the final statements each change exactly one
row; COMMIT. Any failure rolls back everything. **Deletion (T-DELETE)** is one transaction too. **Recovery (T-RECOVER)** at open: a hot
journal is rolled back by SQLite inside the Open lease (the one deletion SQLite may make, shown by the side-file audit); an unpublished
snapshot or an orphaned attempt is dealt with; corruption met there makes the Library Damaged.

**Read boundary (SEC-15/16).** `LibraryCatalog` decodes every stored code through the explicit tables and range-checks every count; names and
paths are exact UTF-16 bytes (unpaired surrogates kept, case variants stay distinct names) and nothing read is used as a path.

**Compile isolation.** Test projects and the App cannot compile against SQLite types (`PrivateAssets="compile"`); tests use `RawSqlite` (reflection
over `DbConnection`) for raw edits and `ReaderConnection.Query` for rows.

## 8. Mutation testing (fault-injected)

`tests/mutation/Invoke-C4Mutants.ps1` applies 22 deliberate defects, one at a time, to a scratch copy and runs the suite that should catch it. Result:
**22 of 22 killed, none survived, none failed to compile** ([evidence/c4-mutants.md](evidence/c4-mutants.md)). The interlock (stale lease, foreign lease,
overlapping windows, id reuse, unclean end, epoch), the store (WAL header, writer-lock sharing, set-aside members), the open checks (fingerprint,
unpublished snapshot), the importer (verification), commit-time lease check, a stable-code mapping, `synchronous`, read-only readers, reader preemption,
and four audit mutants (a seventh P/Invoke, a stray `File.Move`, dropped `PrivateAssets`, an ATTACH statement).

**Honest history.** The first run left seven survivors. Two causes: the scratch copy lacked the package cache (one audit failed in the baseline) and ran
`dotnet <dll>` so the real-process tests could not start their child (nine baseline failures hid kills). After fixing the harness, four survivors were
real test gaps and are now killed by new tests: a stale lease of the same kind while a newer one is current; a foreign lease whose id equals the current
id; a writer lock held by a process that **opened** an existing lock file (the other lock-taking path); a reader that must not be able to write. One
mutant (a Faulted-state guard in the lease end) was shown equivalent (the state also clears the lease id) and replaced by the epoch mutant.

## 12. Judgement calls for the reviewer

1. **Sticky "lock pre-existed".** Recorded at the first acquisition (`_lockPreExisted`), plus `_everHadLibrary`, so that a later Missing state is not mistaken for NotCreated after a Library existed.
2. **Lock-presence quirk.** After opening an empty directory the lock file exists, so the next state is Missing, not NotCreated, until a Library has been created; documented in the tests.
3. **Zero-byte main file** with no side files is treated as uninitialised, not as damage.
4. **Raw SQLitePCLRaw hot path.** The importer's statements run through `raw.sqlite3_*` on the writer's connection handle (typed binds, no `RETURNING`, `last_insert_rowid`) because ADO.NET and `RETURNING` cost about 8 µs per statement and a file row is several statements; ADO.NET remains for everything else, errors are rethrown as `SqliteException` for classification.
5. **IL audit "lease-bound type".** A method counts as lease-guarded if it takes a lease, or is a member of a lease-bound type (a type whose instances are created with a lease), or is only reachable from such methods; this is my interpretation of A-25 (a)/(c) and the reviewer should confirm it.
6. **A-09 numbers** (150/141 against the specification's 164) are asserted as measured (section 7).
7. **K1 and W1 live in Library.Tests** (they need the Library's internals and real child processes), not in IntegrationTests; A-23/A-24/A-26 likewise.
8. **Benchmark data is synthetic** (key order, four files per folder, shared names, a prefilled Library of three snapshots in two sources) and measures the engine, not a real capture.
9. **Verification of the committed snapshot** (a separate read, 3 to 10 s at 2M rows) is independent of the in-transaction verification that is part of the import time.
10. **Spec section 21** was edited only for Q-04, Q-05, Q-07, Q-08, Q-11, Q-12, Q-17, Q-21 and Q-22, each with a pointer to the evidence.

## 14. Measured, fault-injected, inferred, not run

- **Measured:** test results (section 6), audits, native-load experiments, locked restore and reproducibility, benchmarks on two machines, a real full volume on a hosted runner, A-09 counts, the PE imports of `e_sqlite3.dll`.
- **Fault-injected:** mutants (section 8); page-capped `SQLITE_FULL`; hooks that pause or fail inside mutations (W2, L6), a crash between the two set-aside renames, a killed child with a hot journal.
- **Inferred:** that the slow workstation runs were caused by machine load (the quiet-machine runs of the same code reached 127k to 130k rows/s, but the load itself was not measured); that the hosted runner's rates carry over to users' machines.
- **Not run:** a second logon session for K1 (none available here); the real App's own module list for `e_sqlite3.dll` (C5); a clean-VM smoke run of the published exe with the Library; Defender-on timing; SMB, FAT or exFAT Library locations (the path rules refuse network locations; local non-NTFS volumes were not tried for the Library).
